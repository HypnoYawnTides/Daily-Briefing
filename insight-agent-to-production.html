Agent 从 Demo 走进 Production：这一周两条"真实在用"的证据

From showcase to shop floor.
Daily 005 2026-04-21 2 Organizations 2 Sources 4 Min Read
过去一年 agent 相关的公开叙事大多停留在 demo、跑分、showcase。最近几周突然出现另一种口径的文章——4/14 Cursor 披露用 multi-agent 系统给自己的 GPU kernel 提速 38%、4/10 Linear PM Rhea 发文复盘"我们自己团队怎么在公司里用 Linear Agent"——同一周两条"agent 走进真实生产环境里长成什么样"的证据。
CT Cursor 团队 · Anysphere RP Rhea Purohit · Linear
§ 01

Cursor.Multi-agent 跑进了性能关键工程环节

Cursor 团队发文披露他们用一套多 agent 系统给 CUDA kernel 自动提速 38%。↗ Blog 这段话如果只当成技术披露读，它是"我们用了 agent，性能涨了"——很像过去一年无数 showcase。但是换个视角：Cursor 靠自己的推理延迟和成本吃饭，GPU kernel 的 38% 是这家公司利润表上的直接数字，不是演讲稿话术。

这是一件值得 PM 标记的事——agent 第一次真实地进入了一家 AI 公司内部的性能关键工程环节，而不是跑在 demo 路径上。意味着 agent 的风险容忍度已经高到：可以把自家商业模式的关键指标交出去一部分。

"用户正从'好奇 agent'过渡到'敢让 agent 干关键活'。"

对做 AI 工具类 PM 的直接映射：当你的用户开始考虑把 agent 接进关键流程（不是尝鲜流程），产品里的置信度展示、过程可观测、可回滚设计会从"锦上添花"变成采购决策点。你功能表里的"透明度"那一栏，权重该往上调了。

§ 02

Linear.PM 的"产品自用说明书"

Linear 产品经理 Rhea Purohit 发文记录 Linear 自己团队如何使用 Linear Agent——哪些场景派 agent、哪些保留人工判断、agent 输出如何进入人的 triage 流。文章读起来像一份 产品自用说明书。↗ Blog

这篇文章的产品意义不在具体做法，在于它存在本身。对做 PM 工具的同行是一面镜子：当你对外号称"用 agent 重做 SaaS"，你自己的团队有没有先把自家产品里的 agent 用顺？Linear 在公开示范"我们自己在吃自己的 agent 狗粮"——而这件事，正在变成一类工具公司的新合规要求。

"Dogfooding" 从工程文化词变成了营销素材。过去写 case study 要去找一个大客户，现在最具说服力的 case study 是"我们自己"——因为它回答了一个最难的问题：你们对自己的产品有多少信心。

§ 03

Synthesis.这一波增长不是模型能力驱动，是 social proof 驱动

把这两条放到一起看，你会发现它们回答了一个正在浮现的问题——agent 到底靠什么破圈。

过去一年的默认假设是"模型更强 → 使用率上升"。但 agent 的落地呈现出另一种曲线：用户敢不敢让 agent 干活，不由模型多强决定，由他们能不能看见"别人已经真的在用"决定。这是一条 social proof 曲线，不是能力曲线。

所以 4/14 Cursor 这篇、4/10 Linear 这篇的真正产品作用不是技术披露，是 social proof 基础设施——它们把 agent 从"展台"变成"生产线"这件事可视化出来，让后面一波买家有东西可以指着说"像他们那样"。

对做 AI 产品的 PM 有两层启示：

第一，你的案例故事格式要更新。过去一年管用的格式是"before 什么样 / after 什么样 / 提升百分之几"。下一阶段管用的格式是"它在真实生产环境里长成什么样"——怎么嵌入流程、怎么和人协作、怎么在出错时回滚。买家不再被绝对数字打动，他们被"看得见的日常"打动。

第二，公开透明 dogfooding 正在变成采购决策的显性变量。买家的新问题不是"你们效果好不好"，而是"你们自己用不用"。如果你号称卖 AI 产品却不把自己团队挂在这个产品上，你的销售故事会越来越难讲。

一句话总结这一周：agent 的下一程，不靠模型更强，靠"被看见在用"。
