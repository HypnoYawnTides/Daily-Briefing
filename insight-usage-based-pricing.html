AI 工具定价大迁移：从席位制到用量制

When a chat costs pennies but an agent session costs dollars, per-seat pricing breaks.
Daily 009 2026-05-06 3 Sources 4 Min Read
GitHub Copilot 6 月 1 日转 usage-based billing、Notion Custom Agents 推 $10/1000 credits 定价、Cursor 推弹性限额 + 用量分析——三家工具在同一周完成了定价模型的范式转移。底层逻辑一致：当 AI agent 能执行差异化巨大的任务时，按人头收费不再能反映价值。
GH Copilot Billing · Mario Rodriguez NT Custom Agents · Akshay Kothari CR Enterprise Controls · Cursor
§ 01

The trigger.为什么席位制不再适用

GitHub CPO Mario Rodriguez 在公告中说了一句精准的话："a quick chat question and a multi-hour autonomous coding session can cost the user the same amount"。这是席位制的核心矛盾——当 AI 的使用场景从"问个问题"扩展到"自主工作几小时"，固定月费无法反映真实成本差异。↗ Blog

Notion 的 Akshay Kothari 从另一个角度印证了同一逻辑：一个人构建的 Agent 可能惠及整个公司，"价值与席位数脱钩"。当 Ramp 一家公司就创建了 300+ 个 Agent，每个 Agent 的价值差异巨大——有的是简单的 FAQ bot，有的是每天自动扫描竞品动态并更新销售资料的工作流中枢。↗ Blog

Cursor 虽然没有直接宣布转向 usage-based pricing，但发布的企业管控三件套（弹性限额 + 用量分析 + 模型白名单）是 usage-based 的前置基础设施——你必须先能精确衡量和控制用量，才能按用量收费。↗ Changelog

§ 02

Three models.三家的实现路径

GitHub：最彻底。6 月 1 日起所有计划转为 AI Credits（按 token × 模型费率计算），月费不变但内含 Credits 有限。代码补全和 Next Edit 建议继续免费——这是聪明的策略：保持高频低成本功能免费以维持粘性，只对高成本 agent 功能按量收费。企业端引入池化机制，组织内未用 Credits 可共享。

Notion：$10/1000 credits，按 Business/Enterprise 附加项售卖。轻量模型（Haiku 4.5、GPT-5.4 Mini）消耗最高低 10 倍——用模型选择权把成本控制交给用户。规模化配套：单 Agent 额度限制、全局仪表盘、主动告警和暂停功能。

Cursor：弹性限额在 50%/80%/100% 阈值自动提醒，替代硬限额。用量分析支持按产品维度拆分（clients / Cloud Agents / automations / Bugbot / Security Review）。这套工具让管理员第一次能回答"我们的 AI 花费到底花在了哪里"。

"A quick chat question and a multi-hour autonomous coding session can cost the user the same amount."
— Mario Rodriguez, GitHub CPO
§ 03

Implications.Usage-based 的连锁反应

定价模型的变化不只是财务问题，它会改变用户行为和产品设计：

用户行为变化：当每次 agent 调用都有可见成本，用户会更审慎地选择何时使用 agent、使用哪个模型。GitHub 取消了"用完 PRU 后降级到低成本模型"的回退体验——这意味着用户必须主动管理自己的 AI 预算，而不是被动依赖平台兜底。

产品设计影响：Notion 发现轻量模型可以节省最高 10 倍 credits，这意味着产品团队需要在 UI 中帮助用户做模型选择决策——"默认用最强模型"不再是好的产品策略，"智能路由到性价比最优模型"才是。

采购流程重塑：当月费固定但用量可变，CFO 的问题从"批准 N 个席位"变成"设定月度 AI 预算上限"。Cursor 的弹性限额和 GitHub 的池化机制都是对这个需求的回应。

§ 04

Synthesis.对 PM 意味着什么

三条动态串起来的图景：AI 工具的定价范式正在从"按人头"转向"按价值"。

1. Usage-based 是 agent 时代的必然：当 AI 从"辅助工具"进化为"自主执行者"，任务复杂度的方差急剧放大。按人头收费相当于把重度用户的成本平摊给轻度用户——长期来看既不公平也不可持续。GitHub、Notion、Cursor 同周转向说明这不是个别选择，而是行业共识。

2. 管控工具是 usage-based 的前置条件：没有用量可见性就无法按量收费。Cursor 的三件套（model controls + spend limits + usage analytics）本质上是为未来的 usage-based pricing 铺路——先给管理员"看到钱花在哪里"的能力，再转向"按花了多少钱收费"。

3. PM 需要更新自己产品的定价框架：如果你的产品也在集成 AI 能力，需要思考——你的定价模型是否还能反映 AI 功能的真实价值交付？当用户通过你的产品调用的 AI 成本差异可达 10-100 倍时，一刀切的席位价格会让你要么亏损、要么限制用户使用最有价值的功能。

底线判断：Usage-based pricing 不是可选项——它是 AI agent 规模化部署的经济基础设施。PM 在设计 AI 功能时，定价模型应该和产品设计同步规划，而不是功能做完后再"配一个价格"。
