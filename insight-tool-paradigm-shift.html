从 Issue Tracking 到 Canvas：PM 工具和开发工具的形态 4 月同步转向

Two tools, one paradigm shift.
Daily 004 2026-04-20 2 Organizations 3 Sources 4 Min Read
Linear 宣告 issue tracking 已死、Cursor 3 把旗舰产品重新定位为"与 agent 协作的统一工作区"、Cursor 推出 canvases 让用户直接和 agent 生成物互动——三件事发生在不同公司、不同赛道，但形态转向完全一致。
KS Karri Saarinen · Linear CT Cursor 团队 · Anysphere
§ 01

Linear.Karri 宣告 issue tracking 已死

Karri 在 Linear 官网发布了一篇标题克制但内核激进的长文，配合 Linear Agent 产品方向一起推出。文章主论点只有一句话——下一代产品开发建立在 context 和 agency 之上，而不是记录任务。↗ Blog

"The next era of product development is built on context and agency."

把这句话翻译成 PM 工具的行业语言就是：过去 15 年里 Jira / Asana / Linear 这类工具的底层隐喻都是"把事情记下来，让人按记录执行"——工具是记账本。Karri 的意思是，下一代工具的底层隐喻会是"给 agent 足够的上下文和授权，让它们去推进"——工具是调度员。记账本和调度员是两种完全不同的产品形态。

§ 02

Cursor 3.从"AI 辅助编辑器"改称"与 agent 协作的统一工作区"

Cursor 3 不是版本迭代，是一次 positioning 重写。官方定位从 "AI code editor" 换成 "a unified workspace for building software with agents"。核心转变是：编辑器不再是"替你写代码的 AI"，而是"你和多个 agent 协作的空间"。↗ Blog

这个改名看起来小，实际上把产品的核心交互从"人用工具"换成了"人管理一群 agent"。前者用户的主要动作是"按"按钮，后者的主要动作是"分配"和"审核"——是两种完全不同的界面语言、不同的 onboarding 路径、甚至不同的计费模型。

§ 03

Canvases.让用户直接与 agent 生成的可视化互动

紧接着 Cursor 3 之后，团队推出 canvases 功能：让用户可以直接在 agent 生成的图表、UI、流程图里进行互动，而不是等着看最终产物。这个动作补齐了"agent 协作"里长期缺失的一块——过程可见 + 用户干预。↗ Blog

很多 AI 产品只做"输入 → 输出"的端到端，但当 agent 执行时间超过几十秒，用户的参与需求就会自然冒出来——"让我看看它到底在干嘛"、"这一步不对我想插手"。Canvases 给出一个结构化的回答：在 agent 产物上开一块互动画布，用户可以在 agent 还在推进时就介入调整。

§ 04

Synthesis."工具帮你干活" → "工具和你一起管 agent"

把三件事并排摆出来看就会发现：Karri、Cursor 3、canvases 都在解决同一个设计难题——当产品里真正的执行者从"人"变成了"agent"，工具的交互语法应该怎么重写。

Karri 从需求管理侧切入：抛弃"记录 → 派单 → 人执行"的旧模型，转向"context → agent 推进"。Cursor 3 从交互定位侧切入：从"人用 AI"换成"人管 agents"。Canvases 从过程可见侧切入：让用户在 agent 生成过程中有干预面。三条线共同组成一个新范式：工具不再帮用户干活，工具帮用户管理一群帮他干活的 agent。

对做 PM 工具 / SaaS 的同行的直接提醒：

— 你产品首页的核心 value prop 是"帮你更快完成 X"还是"帮你管理帮你做 X 的 agent"？这两个答案对应完全不同的 onboarding、计费、用户分层。
— 你产品的核心交互动作是不是还是"按按钮 / 填表单 / 点提交"？如果是，这套动作在"用户管 agents"的语境下是不够的——至少需要"分配、审核、打断、回滚"这四种新动作作为一等公民存在。
— 你产品的核心度量标是不是还是"任务完成率 / 响应时长"？当执行者是 agents，度量应该换成"agents 交付质量 + 用户干预次数"——后者越低越说明产品成熟。

这次范式转向不会一夜发生，但 4 月里 Linear 和 Cursor 的动作已经把方向亮出来了——值得做 PM 工具的团队正面回应，而不是等行业共识再反应。
