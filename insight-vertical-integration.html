AI 编码工具的垂直整合：从调模型到炼模型

When the tool maker becomes the model maker.
Daily 007 2026-04-23 2 Sources 4 Min Read
Cursor 在 4/21 宣布用 xAI 的 Colossus 基础设施自炼模型，4/23 发布 NAB 6000 开发者标准化部署案例。两件事串起来是一个完整的垂直整合叙事：向上整合算力和模型训练能力，向下锁定企业客户。AI 编码工具公司正从"中间层调用者"走向"垂直整合平台"。
CT Model Training · Cursor NAB Enterprise Case · Cursor
§ 01

Upstream.从调 API 到自研模型：工具公司的上游整合

过去一年，AI 编码工具的竞争焦点是"中间层能力"——谁的 context 管理好、谁的 prompt 写得好、谁在 IDE 里的体验流畅。模型本身是"调来用的"，大家接的都是 GPT-4 / Claude / Gemini，差异化空间有限。↗ Blog

Cursor 的 Composer 系列改变了这个等式。从首代 Composer 到 Composer 2，强化学习规模扩大 20 倍+，以远低于同类模型的成本达到前沿水平。现在拿到 xAI Colossus 的算力支持，意味着它有条件把训练规模再推一个量级。

这是 AI 编码工具赛道第一次出现"工具公司自己炼模型"的明确信号。过去这类公司和基座模型公司是上下游关系（你提供模型，我做好工程化），现在边界开始模糊——Cursor 既是工具公司又是模型公司。

"当工具公司开始拥有自己的模型训练能力，'你家接的哪个 API'不再是核心问题。"
§ 02

Downstream.从个人试用到万人标准化：工具公司的下游锁定

NAB 的案例提供了另一半拼图。一家管理着数千亿资产的澳大利亚银行，在评估了 Amazon Q 和 GitHub Copilot 之后，选择将 6000+ 开发者标准化到 Cursor，并计划扩至 10000+。↗ Case Study

几个值得注意的数据点：Assembly 大型机迁移提速 3 倍（此前因缺 Assembly 人才而搁置多年）、3 周完成原计划 4 个月的支付 app（团队此前无 Kotlin/Android 经验）、首席工程师 Chris De Lorenzo 称"开发速度提升 5-8x，但关键是——我们以前根本不会尝试"。

对 PM 来说，最重要的不是这些加速数字，而是采用路径的变化。AI 编码工具过去的增长模式是 bottom-up——个人开发者觉得好用 → 团队开始用 → 公司默许。NAB 的模式是 top-down——IT 战略层面做评估、做选型、做标准化部署。这意味着 buying criteria 升级了：不再只是"写代码多快"，还要看安全审查、合规对接、管理可控性。

§ 03

Pattern.垂直整合的经典路径：上游控制 + 下游锁定

把 Cursor 这两件事放在一起看，会发现一个经典的垂直整合路径：

向上：拥有算力 → 自炼模型 → 模型性能不依赖第三方，不受"OpenAI 涨价 / Claude 限速"的上游风险。
向下：锁定企业客户 → 标准化部署 → 迁移成本变高，客户黏性增强。

这个路径在科技史上反复出现：Apple 从组装 PC 到自研芯片 + 控制零售渠道，Salesforce 从 CRM SaaS 到收购 MuleSoft + 控制数据集成，Tesla 从买电池到自建 Gigafactory + 直营销售。每一次垂直整合的共同逻辑是：中间层做到极致后，必然向上下游扩张。

Cursor 目前处在这个路径的早期——模型训练还在用合作方的算力（xAI Colossus），企业客户的标准化部署是一个 case 而非普遍现象。但方向已经很明确。

§ 04

Synthesis.对 PM 意味着什么

如果你在评估 AI 编码工具（给自己团队用或作为竞品参考），决策维度需要升级：

1. 模型自研 vs 调用：工具的核心智能是自研的还是调第三方 API？自研意味着性能迭代不受上游节奏限制，但也意味着研发成本更高、模型 diversity 可能更低。
2. 算力来源：自研模型的算力从哪来？自建、合作、还是按需购买？这决定了工具公司在 AI winter（如果来的话）的生存能力。
3. 企业锁定深度：标准化部署后，迁移成本有多高？数据 / 配置 / 工作流的可移植性如何？
4. 上下游风险：纯 API wrapper 类工具面临上游涨价 / 限速的风险，垂直整合类工具面临"自研模型不如第三方好"的风险。两种风险的对冲方式不同。

底线判断：AI 编码工具赛道正在从"中间层工程化竞争"进入"垂直整合平台竞争"。纯粹靠 prompt engineering + context management 做差异化的窗口期在收窄。
