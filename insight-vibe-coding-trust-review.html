Vibe coding 进入信任审查期：从 hype 概念到需要产品责任的 stack

When the vibe becomes a responsibility.
Daily 006 2026-04-22 2 Sources 4 Min Read
Replit 在 4 月 20-21 的两次公开动作——Luis Chávez 的《Defense in Depth》长文 + 产品化的 Security Agent——串起来看是一次姿态重排。Karpathy 2025 年初造出 "vibe coding" 这个词至今一年，它第一次被当成需要全栈防御的 stack，而不是炫技 demo。
LC Luis Chávez · Replit SA Security Agent · Replit
§ 01

Stack.Vibe coding 第一次被当成可建模的三层 stack

Luis Chávez 的文章里，vibe coding 不再是"你跟 AI 聊聊它就帮你写代码"的模糊描述，而是一个有明确架构的 stack：生成代码的 AI 层 / 运行代码的沙箱层 / 部署代码的权限层。每一层都有自己的失败模式，都需要独立防御。↗ Blog

这个框架把一个抽象的 buzzword 变成了产品术语。过去谈 vibe coding 没有共同词汇——每家的"AI 写代码"都不一样，买家也说不出自己想要什么。现在有了 stack 视角，讨论就可以变得精确：你家的沙箱隔离到什么程度？你的 AI 层和部署层之间有 human-in-the-loop 吗？权限粒度是 repo 级还是 file 级？ 这些问题是 stack 被建模后才能被提出来的。

"vibe coding 终于有了可以和甲方 checklist 对齐的词汇表。"
§ 02

Product.Security 从 feature 升到独立 agent

同一天 Replit 发布 Security Agent——一个**独立的、监控 AI 生成代码安全问题的 agent**。这是一个产品化层面的 signal。↗ Blog

过去一年 AI 安全工具大多嵌在 IDE 里做一条 linter 规则或一个小图标；现在它是独立 product，甚至是独立定价的 agent。这通常意味着市场结构的微调：某个买家群体已经足够大、愿意单独为这个能力付钱。Replit 把 Security 单拎出来做 agent，不是在 feature 层面做差异化，是在 产品品类层面 做差异化——它在赌："会有一批买家愿意为'专门有 AI 安全监控'这件事付钱"。

对做 AI 编码工具的 PM：盯住竞品"内嵌能力独立商业化"的动作。那个动作是一个市场发出的信号——某能力已经进入"愿意独立付费"的成熟度。如果你的工具里也有类似能力（agent 行为审计、权限细粒度、沙箱日志可视化），可能到了独立包装的时候。

§ 03

Synthesis.分水岭不是能力，是责任

把这两件事放在一起，会发现一个不太好听但对 PM 特别重要的真相：vibe coding 的下一程不是"AI 写得更好"，是"谁来对后果负责"。

过去一年比赛的是"AI 能写多复杂的代码"——上下文窗口、多文件编辑、repo 级理解。那条赛道的冠军很明确（Cursor / Claude Code / Replit Agent 都在同一梯队），差距也越来越小。但赛道之外冒出来的新问题，是一年前没人问的：

你输出的代码谁负责？ 如果 AI 写的代码带 SQL 注入，被攻击，账由谁担？
你的沙箱跑谁的任务？ 如果用户要 AI 执行"我们生产 DB 备份一下"，sandbox 有没有边界？
你的部署权限给谁？ 如果 AI 一键 push 到生产，谁来 review、回滚？

这三个问题是 vibe coding 从 hype 到 production 必须回答的。Luis 的 Defense in Depth 从架构侧回答；Security Agent 从产品侧回答。两个动作合起来是一个信号：Replit 已经把 vibe coding 当成"对用户负责的产品"来维护，而不是一个 demo 时期的炫技 feature。

对 PM 的最终映射：你在评估 AI 编码工具（给自己团队用 or 作为产品参考）时，buying criteria 需要升级。过去问"它写得多聪明"，未来要问：

1. 沙箱是每个 session 独立的吗？还是共享的？
2. 生产环境部署有没有 human-in-the-loop？
3. 有没有 agent 行为审计？出问题后能查到谁让它做了什么？
4. 权限最小化是怎么做的？AI 能 sudo 吗？

这不是安全工程师的问题，是 PM 在产品决策时就要纳入的 criteria。因为 一旦这些问题出事，负责的是产品，不是安全部门。
